# 手机更新的资源与缓存开销

更新分为游戏本体、完整人物对白、2K片头影像。后两者独立保存；基础包包含全部必需画面、书页、代码与开局对白，具备基础包后可继续故事。完整标记只对应这组必需文件，不宣称可选资源已经下载。

此前单个2K片头为13,245,317字节，加封面后占必需包约61%。此次不重新编码或降低画质，而是以独立影像清单、持久缓存与完成标记管理。在线影片地址不变；旧版同一影片可在SHA检查后复用，未保存影片的离线玩家可通过文字入口开始故事。

手机资源下载器最多两路并发，按清单预分配接收缓冲，消除完整chunk集合再拼接的额外大数组；入口安装仍独立处理少量代码与字体文件。文件核验与缓存写入间周期性让出执行机会；同版本的正确缓存不再重写。语音的流式进度通知节流，避免每个小传输片段触发界面更新。文件大小、SHA、MIME、传输块及其成员校验保留。

Service Worker安装先检查同项目旧入口缓存，按实际内容验证复用；存储失败不改成冗余网络重下。缓存影片GET Range使用Blob切片，HEAD及无效Range只返回元信息；设备无法转存影像时，可继续读取已经验真的旧副本。旧缓存、存档、版本和多窗口保护仍保留。

独立更新页增加暂停和字节/百分比进度。暂停保留完整且验真的文件，不承诺未完成文件的按字节续传。基础资源、影片和语音的保存操作互斥，避免手机同时进行多套校验和存储。

验证使用此前及当前两份真实生产构建，Node中执行其实际worker脚本和对应下载模块，以相同可控响应块提供真实构建文件。记录请求原始字节、缓存数据写入、暂停/恢复、真实引擎生成的存档与收藏、多窗口和离线Range。结果见[MOBILE_UPDATE_VERIFICATION.json](MOBILE_UPDATE_VERIFICATION.json)。脚本还核对旧影片指纹不变和新包未请求可选影片。

该受控环境不是真实手机、浏览器Cache API实现、传输压缩或地区带宽测试。原始资源体积减少不能直接当作相同比例的下载时间提速；Blob方法检查也不承诺浏览器内部零拷贝。先前浏览器来源访问限制仍生效，本次没有替代浏览器控制或伪造手机截图。
